# 0016 — 没有谁的消息要求的压缩，是摊位向场讨来的一次唤醒

> **语言：** [English](0016-a-wake-is-the-fields-clock.md)（主文档） · [中文](0016-a-wake-is-the-fields-clock.zh-CN.md)

**状态：** Accepted（2026-11-21）—— 同日落地：`__on_timer` hook、tag、注册点都在 `crates/booth`（见「后果」）
**日期：** 2026-11-21

## 背景

本仓今天跑的每一次压缩都诞生在一个 turn 之内：流式循环在拉答案的同时开出侧分支（`open_tail`），由 drain 把产物落到 checkpoint 门（`raise_tails`，2026-11-21 —— 分支现在活过开它的那个 entry，而不是把 entry 顶住最多六十秒）。

有两种情形在那个形状里没有位置：

1. **分支永远不落地。** `raise_tails` 把分支交给常驻 guest 里的一条线程，于是 turn 不再等它 —— 也就意味着 turn 不再是发现它失败的那个东西。worker 死掉、provider 回错、或者 store 在它底下把 span 关掉，都会留下一个打开的压缩节点：会话答复一直说 `compressing: true`（`SessionDto`，`mem-server/src/lib.rs`），而本仓没有任何东西再看一眼。该频道里的下一条消息会读到、看见打开的节点，可能再开一个分支；一个不再有人写的频道，则让这个 span 永远开着。
2. **起因不是消息的那次压缩。** k10r 的判词是在读取时算出来的 —— 欠不欠、欠什么，是有人来问的时候才决定的。而一个策略时刻（「这段上下文闲得够久，可以折一次」）不产生读取，因为读取是 turn 干的事，而 turn 需要一条消息。

后半截的机制并不缺，也不属于本仓。它在 aura 里已经落地（那边的 ADR-0016）：每个 realm 一条 `DelayQueue` driver，deliver 条目变成一个 `__on_timer` job —— `deliver_timer` 只送 `{tag}`，送到当初注册它的那个实例（`realm/src/instance.rs`）—— 桥上有 `ctx.timer.register {at_ms, tag, durable}`（`realm/src/ctx.rs`），durable 注册写成 ns 27 的行，启动时凭这些行重建轮子。最小 host 会拒这条臂（`induction-host` 的 `timer_register` 原话是「mudra has none today」）；场的 host 提供它。所以 gravity 缺的不是一个时钟，是一句从未问出口的话。

## 决定

### 1. 时钟是场的；本仓只发问

自己安排睡眠的摊位是场看不见的摊位：睡眠随进程死掉，别的部件无从取消它，场重启之后那个安排留在一个已经不存在的线程里。aura ADR-0016 已经以同样的理由否掉了「每个计时器一条 task」，只留每个 realm 一条 driver。gravity 只注册与取消，从不睡觉。

### 2. tag 是摊位自己的指针：`compress:<channel>`

投递只带 `{tag}`，别的什么都没有；而 guest 也从不被告知自己的实例键 —— 这个摊位不读任何 `IND_*` 环境变量，也没有哪一帧写着它自己的名字。于是唤醒必须知道的那些东西，只能靠摊位当初装进 tag 时带过去。gravity 的 tag 形状是 `<意图>:<频道>`，且只有一个函数解析它；解析不了的 tag 要把那个读不懂的 tag 打印出来，而不是静悄悄地什么也不做 —— 一个无声的错配，就是一个永远为着无人能指名的频道而响的唤醒。

### 3. 唤醒是发问，不是命令

处理函数重新读一遍 tag 指名的那个频道的投影，只有 store 仍然说 `compressing` 时才动手。欠不欠活，唯一权威是 store 的答复：span 可能已经被后来的一轮 turn 落地了，也可能被另一个进程落地了。计时器说的是「再看一眼」，从不说「压这个」。这也正是两个 pass 不会叠在同一个 span 上的原因 —— `compressing` 这个标记本来就是为这件事存在的，而一个无条件压缩的唤醒，会为一个已经在飞的摘要付第二次模型钱。

### 4. durable，因为窗口活过驻留期

gravity 的实例在 idle TTL 之后被逐出，而一次压缩唤醒要覆盖的窗口按构造就比它长（aura ADR-0016 §1 点的正是这个情形：cache 时钟的检查）。在被逐出的实例上装一个内存档计时器，是一个蒸发了的安排 —— 而它本来要落地的那个 span 继续开着，于是又回到失败形态 1。所以注册要用 `durable`，它写下的那行就是安排能活过重启的原因。

`induction_guest::Ctx::timer_register(at_ms, tag, durable)` 带这个标记（2026-11-21：第三个参数，由 `timer_args` 构造，`the_timer_arm_carries_the_durable_ask` 钉住帧的形状）。最小 host 仍然拒这条臂 —— 不维护计时表的 host 兑现不了「活过重启」这个请求，拒掉比留下一次事后无人能找到的唤醒更诚实。

### 5. 重新装填是显式的、从当下算，并且在 turn 之后隔一个延迟才装

发现自己的 span 仍开着的唤醒，要么开分支，要么（材料还没到时）按当下这一刻装下一次唤醒。它从不预先装一串，也从不为睡过去的那些时刻补一轮爆发：aura ADR-0016 §3 已经裁定跳过而不是补齐，而停机之后一串压缩，正是压缩策略当初要避免的那种形态。

一轮 turn 只装一次唤醒，装在「投影要求压缩」之后六十秒（`WAKE_DELAY_MS`）—— 不是一个分支一次，也不是在答案写出来之前。六十秒是策略数字，不是结构数字：长到还在拉的分支有机会先落地（对着一个在飞的 span 再开一个 pass，一份摘要付两次钱），短到死掉的分支在会话还新鲜的时候就被注意到。撞上已关闭 span 的唤醒只花一次读取就停下。

### 6. 唤醒是维护：它不写往来行

唤醒走的是 turn 用的同样两个落地门 —— 摘要走 checkpoint，事实走 memory 门 —— 别的不写。它不写消息行，不往频道的 UI 流里 emit，也不出现在它所维护的那段会话里。以「有人说话了」的样子出现在产物里的维护，是产物的缺陷，不是机制的细节。

### 7. 它以第三个 entry 进入摊位，与其余的门同一道闸

`__on_timer` 与 `turn`、`save` 并列声明（`.on("__on_timer", …)`），并且坐在 `turn` 同一道闸后面，因为它花的是同一份能力：它调模型、写 store。写不了的唤醒没有用；不设闸就能写的唤醒，是一个和不设闸的 turn 同样大的洞。

## 诚实的语义代价

- **重试出来的压缩，不是死掉那一次本该产生的文字。** 材料是从日志重新取的 —— 同样的行 —— 但模型不是确定性的，所以被唤醒落地的 span 可能带着一份与死掉的分支措辞不同的摘要。权威是日志；摘要是它的一次渲染。
- **撞上已关闭 span 的唤醒是一次白读。** 代价是一次投影读取，别的没有。为了省掉它而让摊位自己记账 span，是 store 的活，而且按定义必然过时。
- **tag 是本仓两次运行之间的契约。** 改了格式没改解析，就是一次为着无人能指名的频道而响的唤醒；所以解析失败要出声。
- **durable 的唤醒活过装它的那次部署。** 配置在唤醒挂着的时候被换掉，摊位会以新配置醒来。唤醒问的是日志，所以这是对的而不是不幸的 —— 但它同时意味着唤醒不能携带一个决定。

## 备选方案

- **在 guest 里睡一条线程。** 随进程死掉，取消看不见，重启活不过来。aura ADR-0016 以同样三条理由否掉了「每个计时器一条 task」。
- **让 k10r 来安排唤醒。** 它握着策略、算着判词，但它不拥有模型：它的答复说的是欠什么，从不说谁能做。一个给自己安排做不了的活的 store，是一个中间有洞的调度器。
- **场地侧的 cron（prism）。** 这个 pass 必须跑在「键就是该频道」的那个实例里，因为它折的材料就是那个实例的投影。为一个摊位配第二个调度器，就是 span 一直开着时要看两个地方。
- **无条件压缩的唤醒。** §3 已否：任何 turn 正在压的 span 上，它都要付双倍模型钱。

## 后果

- gravity 多出第三个 entry（`__on_timer`）、一个 tag 解析函数、一处注册点：以 `compressing: true` 结束且没有落地摘要的 turn 会为该频道装一次唤醒；而开了分支的唤醒，也顺手把「本来会开同一个分支的那一轮 turn」挡在外面。
- **随本记录一起落地**，都在 `crates/booth`：`.hook("__on_timer", …)`（是 HOOK 不是 `.on(…)` —— 名字是 host 的，induction 拒绝把它当订阅）、投影要求压缩之后的 `arm_wake`、`<意图>:<频道>:<成员>` 形状的 `wake_tag`/`parse_wake_tag`、作为唯一判据的 `wants_compress`，以及被抽出来的 `branch_material` —— 于是分支的前缀只从投影推导，不再依赖某一轮 turn 自己的状态。装不上只记一行日志，绝不让它要守护的那一轮 turn 失败。
- **host 投递的名字要改四处，因为词汇是复制的。** `__on_timer` 必须同时加进 induction 的 guest、aura 的 booth builder、effector 的 python 与 steel 两个载体 —— 同一个数组的四份拷贝，各自用同样的话拒掉这个名字。这次落地让它们一致了；没有任何东西让它们保持一致，而这就是下一个保留名被发明之前该修的形状。
- 测试：`a_wake_folds_a_span_that_no_turn_is_watching`（真 store，投递走 `Realm::deliver_timer` —— 轮子自己调用的正是这个函数 —— 全程没有 turn：摘要落地，日志里只有它折掉的那些记录）、`a_wake_only_acts_on_the_stores_verdict`、`a_wake_tag_names_its_channel_and_member_and_reads_back`、`a_branch_sees_the_head_the_summary_and_the_numbered_records`。
- **`durable` 这个请求已经到了 guest 这一侧**（2026-11-21）：`Ctx::timer_register` 把第三个参数带上，帧也带着它，于是 §4 的残项在这一侧关掉了。仍然开着的，是本仓自己的接线 —— 见下一条。
- 接线落地时要补的测试：一个投递 `__on_timer` 的桩 host，断言分支经 checkpoint 门落地；一个 span 已被别的写者关闭的唤醒，断言摊位什么也没写；一个解析不了的 tag，断言这次错过被打印出来而不是被吞掉。
