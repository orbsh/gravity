# 0012 — 数据路径不归 venue

> **Languages:** [English](0012-the-data-path-is-not-the-venues.md) (primary) · [中文](0012-the-data-path-is-not-the-venues.zh-CN.md)

**Status:** Accepted (2026-11-18)
**Date:** 2026-11-18

## Context

一次 turn 产出的不只是文字：一份生成的报告、一份抓下来的数据集、一个构建出来的镜像、一个必须从产出机器送到需求机器上去的文件。venue 是每个客户端和每个节点都已经连着的那一个地方，于是它成了路由这些字节的显然选择——而这正是本条记录要指名的错误。

两件事决定了结论。venue 的连接面承载的是设备连接和节点 mount，它的容量是为指令准备的，不是为载荷。而 turn 真正的活发生在节点上，紧挨着它产出的数据，处在一个可能本来就放着这个文件的执行环境里。

## Decision

**裁定——控制面只传指令与结果摘要；产物由节点自己搬运；节点能到达什么，是 skill 的声明，不是 venue 的。**

1. **结果保持 message-sized。** 回到平面的是答案本身，不是答案所涉及的那些产物。工具的结果只点名它产出了什么——一个路径、一个引用、一个计数——就像一条命令打印位置而不是打印文件。
2. **产物由执行它的操作自己搬运。** 一个产出大件的步骤，把它写到该去的地方：节点的本地文件系统、部署自己的传输工具，或者 skill 声明的一项传输操作。gravity 的调用参数是指令语义——路径、选项、片段——它们因为是指令而有界。
3. **可达性是 skill 的属性。** 一个节点究竟能不能到达某个目标（直连、同一个 VPN、该机器上存在某个 mount），随 skill 声明在 gravity 一侧。venue 既不知道也不治理它：它把事件送到一台设备、送到一个 mount，对这两者之间能做什么没有意见。
4. **平面上的入站上限只防异常。** venue 门口的大小限制之所以存在，是为了一个畸形或敌意的帧不能把它撑爆。它不是数据面设计，在那里选定的任何阈值都不得被读成对"结果能有多大"的表态。

## Considered and rejected

- **让产物经由 venue 中继，好让一切都走一条通道。** 这会让平面成为每一个产物的带宽，而这份成本随工作量的大小增长，不随平面的本职（把指令送达 booth 与节点）增长。资源路径上有同一个拒绝：material 由平面铸出、由节点直接花费（effector ADR-0003 §8）——真正要保住的性质是"没有任何东西被中继"，不是"没有任何东西跨过"。
- **把可达性写进 venue 的路由表。** venue 持有设备、连接与 mount。它不知道一个部署的网络拓扑，而这份知识在平面上的第二份副本必然与它所描述的那些机器漂移。
- **把字节装进 tool call 里。** 调用是指令；字节装进去，控制面就在事实上变成了数据路径，而每一次重放这个调用的跳数都会重放这份载荷。
- **把传输凭证交给下发的代码，让它自己推。** 这等于把一份数据面凭证放进执行未经审查代码的那个环境——正是 resource contract 存在的理由。

## Consequences

- 搬运数据的 skill 声明它需要的传输方式；turn 传的是路径与选项。传输本身在 venue 里没有任何建模。
- 数据路径的失败是操作的失败，作为模型能读到的一条 tool 结果上报。venue 自身的健康对它一字未提。
- venue 的吞吐从不以产物大小计量，因此对它真正重要的数字（连接数、派发延迟）保持有意义。
- 相关：effector ADR-0003 §8–§9（material 由平面铸出、由节点花费、从不中继；`EFFECTOR_RESOURCES_ROOT`），以及本仓 ADR-0001 §7（mount 由 manifest 到达，不是由模型编的名字到达）。
