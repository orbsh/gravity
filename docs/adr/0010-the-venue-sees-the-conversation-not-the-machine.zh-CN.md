# 0010 — 场域看见的是对话，不是机器内部

**状态：** Accepted（2026-10-31）
**不取代任何文档。** 它把 ADR-0009（一轮，两种呈现）扩展到他没回答的那个问题：一轮里哪些事实会被说给场域。

## 背景

一轮会把学到的一切写进自己的日志：问题、每次工具调用及其参数与结果、每条补全支路、压缩摘要、复盘事实、答案、收尾记录。键里带着 `channel:turn`，所以这些都可有址、可重放；客户端取会话时看到的，是日志已经做过的整理（ADR-0024 §5）。

「说」是另一件事。到目前为止 booth 只发答案的 chunk 和结束，缺的正是那个点明轮次的回执：客户端没法把自己刚发出去的那句话，跟旁边到达的答案对上号；而其余事实根本没有规则说它该不该被说。一件一件往上加事件，答案流迟早会被「容易发的东西」填满。

## 决定

**事件承载的是「有人在看着这一轮时，此刻必须读到的东西」。机器要继续、要审计、要重放所需的一切留在日志里。**

这条规则有两条可以检查的推论：

1. **日志是记录，说出的内容是它的投影。** 没有哪个事件可以带日志里没有的事实——否则人看到的对话无法从存储重建，两者会在没人发现的情况下分叉。
2. **只活在事件里的事实不存在。** 值得看就值得写；没写，就不是这一轮的事实。

| 这一轮的事实 | 场域 | 理由 |
| --- | --- | --- |
| 问题本身 | **日志**（写它这一行即发号） | 由发出它的客户端呈现，不由 booth 复述 |
| `ui:turn.opened {turn}` | **发**，发号后立刻 | 发送方需要在答案之前拿到号，才能给自己那句话作键；没有它，同一对话的两轮在其起点就无法分开 |
| 答案的 chunk | **发** | 答案本身就是「说的话」（ADR-0009：给渲染器的是帧，给程序的是 `{delta}`） |
| 模型自己的推理 | **都不发** | 它不是答案，也不是这轮对话的记录。「展示思考过程」应是它自己名下、由客户端主动选择的一个事件，绝不能混进答案的 delta 流，也不能悄悄开第二条流 |
| 工具调用（`invoke_skill`） | **日志**记全（参数、结果）；**至多**发标题与状态 | 人要读的是在做什么、成没成；载荷是机器事实，把它放到答案流上等于把日志复制到线上 |
| 记忆检索（`recall_memory`） | **只进日志** | 记忆内容不是这段对话，把检索内容送上流是没人要求的泄露面 |
| 压缩、复盘支路 | **只进日志** | 那是记录的维护，不是在对话里发生的事 |
| `ui:turn.done` / `ui:turn.error` | **发** | 结束是「说出来」的，不是返回的（ADR-0009） |
| 配置类门（模型保存、界面、布局） | **发**，不带 turn | 它们不属于某一轮 |

凡属于某一轮的帧，信封上都带 `turn` = `<channel>:<turn>`（日志键的前两段），与 `name`、`data` 并列。

## 画出来的形状

对话流里一次交互，按实际发生的顺序。新的交互照抄这个形状；渲染器里没有任何针对它的特例。

1. **客户端发一个事件**，带上人做了什么——一轮就是那段文字——以及（如果调用方要画面）要画进哪些槽（`rack` = 列表，`text` = 区域）。客户端什么都不画：它没有业务逻辑，因此不知道「一条消息」是一行、这一行放进 rack、这一行长什么样子。按钮、表单同理，也是一样的处理：只有应用知道它意味着什么。
2. **存储写入那一行**，把这次动作变成事实——写就是发号的地方。
3. **应用先说话，再干活**：先是回执（`{turn}`），然后一批操作：把用户这一行 append 进 rack、建好答案要流进去的区域、append 读这个区域的气泡。在飞的一切都带同一个 `turn`。
4. **这时才开始干活**。答案的每个 chunk 都 patch 开场时建好的区域，不再重画舞台。
5. **结束要说出来**（`done`，或带原因的 `error`）。失败也留着用户那句话——那是事实：他确实发了。

容器的形状归应用，活在帧里，不在渲染器里：用户行与回复行是同一个 rack 里的两行，两者的差别（靠末端对齐并带强调色，对比铺满且朴素）就是帧携带的类名清单。一个从没听说过「对话」的渲染器也能把两者画对。

帧里明确**没有**的东西：一行停多久、要不要淡入淡出、列表跟不跟尾巴。那些是渲染器的词汇（fluxen ADR 0024：服务端送行，呈现归 UI）——这是同一分工从另一侧看：应用不描述效果，渲染器不发明行。

## 后果

- 漏收 `opened` 的客户端仍能从首个 chunk 的 `turn` 找回号；两个都漏，它对顺序一无所知，只能重取会话。
- 以后加「步骤」事件不动任何既有流：新名字、同一种信封，不认识它的渲染器忽略即可。
- 推理 token 从场域不可达。这是刻意的：把模型的草稿本当对话记录展示，等于对答案做它支撑不了的断言。
- 日志严格多于场域所见，所以「人看到了什么」是日志加这张表算得出的函数——不必再留第二份记录。
