# 0006 — 协作是并行度，不是消息

> **语言：** [English](0006-coordination-is-parallelism.md)（主文档） · [中文](0006-coordination-is-parallelism.zh-CN.md)

**状态：** Accepted（2026-10-28）。对 turn 执行器的常设约束；本身不需要实现工作。
**日期：** 2026-10-28

## 背景

Gravity 是模型做决定的地方。一个 turn 由客户端（prism、CLI）或场域触发器打开，跑一次 LLM 流加工具调用循环，然后把 delta 追加回会话。可能同时有很多 turn 在跑、跑在很多节点上、服务很多目标——这里说的「多 agent」指的就是这件事。

本记录要定的是：这些 turn 之间是否还要**互相说话**——信箱、订阅、agent 间协议、MCP 客户端、由 supervisor 指挥 worker。现行框架对其中若干项答「是」。这套矩阵全部答「否」，理由不是口味。

两件事让这个答案成为结构性的。

其一，目标形态。这套栈不是为一个主人、一个工作目录的个人助手做的，而是为超级个体组成的液态化组织做的：编组按目标成立，任务结束即解散。在那个形态里「谁能做什么」是实时状态——能力边界随使用漂移，权限是拓扑。消息面假设的恰好相反：参与者可枚举、对端可寻址、两点之间的通道值得单独维护。重组一开始，这三条都不成立。

其二，算术。通知式协作的成本是每一对一条需要维护的通道：N 个 agent 就是 N(N-1)/2 条，broker 也只是把它换成 N 条通道加一个拓扑单点。成本不在带宽，在每条通道必须协商的语义——身份、能力声明、schema 版本、超时、重试、投递语义、幂等。到液态组织那个数量级，通道层本身就是故障面，不是能力。

## 裁决

**RULING — gravity 不参与任何 agent 间消息。协作是基底里的状态，并行度来自任务图的拓扑。**

1. **一个 turn 一个输入一个输出，没有收件箱。** 输入是 turn args 加会话投影，输出是会话追加。边界上不跨任何别的东西：没有消息队列、没有信箱、没有未读游标、没有确认。一个 turn 想让另一个 turn 发生，就写下让它发生的那个事实（一个任务顶点、一条记忆事实），然后结束。

2. **没有协议客户端，没有工具注册表。** gravity 不说 MCP、不说 A2A、运行时也不注册任何工具：工具列表固定、硬编码、按组划分，每一条都是这套栈自己的门（ADR-0004）。协议面用「陌生实现之间的互操作」来付账——这里没有陌生实现，所有对端都是同一套栈、由同一张部署清单发出。协议会额外带来一个动态信任面：能在运行时热插拔工具或对端，就等于能在运行时改写能力边界。

3. **协作是状态，所以写状态的工具就是任务门与记忆门。** `open_task` / `move_task` / `list_tasks`（k10r 的任务面，k10r ADR-0021）与 `commit_memory` 是一个 turn 让工作对其他 turn 可见的方式。并发随之而来：一个未被填写、依赖已满足的任务顶点就是可做的工作；图的输入是调度器的输入，不是一队消息。依赖是一条边，不是一条必须有人收到的请求。

4. **看起来像通知的东西属于场域，不属于 gravity。** 激活 turn 的定时器或任务事件是 Aura 的事件面（摊位激活）；它产出的那个 turn 仍然从会话投影开始，而不是从某位同事递过来的一份 payload 开始。gravity 不发射面向 agent 的事件，也没有哪个组件的 turn 是由 gravity 朝它投递东西打开的。

5. **故障面留在本地。** 没有投递，就没有投递语义要设计：没有在途消息会丢、没有重复要去重、没有顺序要保证、没有反压要协商、也没有重试会把模型再跑一遍。一个 turn 要么把结果写进基底，要么向它的调用方显式失败。

## 已考虑并否决

- **在 k10r 里为每个 turn 开一个信箱。** 那会把基底变成消息存储，给每个 turn 引入未读/确认状态，并在会话日志与事实图之外再造一个真相源。
- **接一个 A2A 或 MCP 客户端，好让一个 turn 委派给别家的 agent。** 这是协议唯一真正划算的场景——而它划算的地方（异构的陌生实现）这套栈没有。要跨边界委派，就是经 prism 提交一个带自己会话的 turn，那条路已经存在。
- **把 Aura 场域事件当 agent 指令通道（pub/sub）。** 场域事件是引擎的运行时路由面（摊位、key、持久队列）；用它承载 turn 之间的语义指令，等于把认知层的寻址焊到运行时的寻址上，并把 agent 语义塞进一个为摊位解耦而造的机制里。
- **一个 supervisor turn，拆解工作并指挥 worker turn。** 它把消息层重新造了一遍，只是载体换成 prompt 文本，还多出一个必须被观察与重试的跳数，让质量变成跳数的函数。拆解是 `open_task` 加 `next` 边；worker 读图。
- **用消息在 turn 之间传上下文，而不是走共享记忆。** 同一份知识的两个存储必然漂移；会话日志与图是后来的 turn 唯一查看的地方。

## 后果

- **并发由基底决定，不由 broker 决定：** k10r 的写路径与各节点的 mount 容量决定同时能跑多少。扩容量是部署问题，不是路由问题。
- **审计线索就是图与会话日志。** 关联 agent 行为意味着读事实、任务顶点与追加记录——没有消息日志可以 join，也没有「谁告诉了谁」需要重建。
- **任务门必须存在、并且留在固定列表里**，这条裁决才有意义（ADR-0004 §2 第三组）。一个答不出 `list_tasks` 的基底，会让它的 turn 互相看不见对方的工作，而想加一条通道的诱惑就会回来。
- **未决：** 新开出的任务如何变成一个 turn（场域侧，Aura 的事件/定时面），以及一个任务顶点是否需要 claim 或 fence，使两个 turn 不会领取同一份可做的工作——那是任务图语义，归 k10r 的任务面，不归本记录。
