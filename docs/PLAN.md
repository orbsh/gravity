# PLAN

Design lives in the wiki (stateless-agent-architecture.md / krystallizer.md); this file only sequences phases.

## Milestone A — Local turn executor

- [x] Phase 0 — Workspace skeleton: `crates/{core,cli,config}`. One happy-path turn: fetch_session (full mode) → LLM call → append delta. No tools yet; plain chat against Krystallizer.
  LANDED 2026-10-10: `MemorySurface` seam (in-process `ChannelStore` wrap / mem-server `HttpSurface` — ADR-0007 as revised: HTTP is the single cross-process form, in-process is a local detail); config takes `store_path` or `store_url` (store_url wins); turn contract tests run the same assertions through BOTH surfaces against a real mem-server (failed turn appends nothing, one-ts-two-subs delta, checkpoint pruning flows through the seam). Turn body copy in the seam test stands in for the LLM stub until LlmClient grows an injectable transport (Phase 1).
- [x] Phase 1 — LLM layer: the provider is a SEPARATE booth type, not gravity-internal plumbing (aura ADR-0034; ADR-0031's ruling applied: outbound access lives in a booth's own code). Provider booth = Rust over the induction pipe (`reqwest-eventsource` SSE against OpenAI or any OpenAI-compatible endpoint, parsed into a producer that answers each pull round with an envelope and closes with `done: true`); key custody via env injection, never in the module or args; transport-level retry/backoff lives here. Gravity consumes it through `ctx.iterate(provider_booth, handler, args)` — a native pull loop. Responsibility cut: model selection, fallback, circuit breaking, transcript-aware retry STAY gravity-side ("LLM identity stays Gravity-side" — cache binding, untouched). Local CLI (Milestone A) may call the provider code path in-process during bring-up, but the production shape is booth-over-iterate: the sibling booth is the access method. Prompt-view byte-stability contract test (fetched view prefix must be byte-identical — context-cache correctness depends on it).
  LANDED 2026-10-13 (mostly with Phase 4.1 — the provider guest IS the streaming provider; the phase closes with its residuals): ① the SSE wire decoder has ONE home (`gravity-core llm::sse`, gravity `72886a5`) — the provider guest and any streaming consumer share it, the transport stays with the caller (feed/decode protocol, no reqwest-eventsource needed: the guest is a sync process, `ureq`'s blocking reader IS the pull backpressure). ② transport retry (gravity `931c75b`'s follow-up): constant backoff, 3 attempts on transient failures (connect errors, 5xx); a 4xx fails through on the FIRST attempt — retrying a 401 is just delay. Two contract tests lock both. ③ prompt-view byte-stability (`crates/core/tests/prompt_stability.rs`, 3 tests): same state assembles byte-identical views across BOTH surfaces (in-process and HTTP each own their store — one fjall directory = one process, ADR-0007, so the cross-surface assertion compares the same logical conversation, not the same directory); appended history is a byte prefix of the next prompt (append-only, prefix cache hits ride it); checkpoint compression is the ONE deliberate rewrite (documents the boundary). Residual (recorded, not owed): the CLI's `LlmClient::complete` is still non-streaming blocking — Milestone A's bring-up path, Phase 2's tool loop decides whether it collapses into the streaming face.
- [ ] Phase 2 — Tool-call loop: parse LLM tool calls → dispatch to Probe → record tool_call/tool_result into delta → feed back. One mode only; no privileged calls. Delta boundary: only this turn's additions, never a full-session write-back.
- [ ] Phase 2.5 — Transcript/history split + cold-call declaration: the in-turn tool loop keeps a working transcript in resident memory (calls, errors, retries — what the next LLM inference needs); session history receives only the net effect at turn end (intermediate failures are process, not memory). Every tool declares its execution nature at registration (fast/idempotent vs human-touch/external — declared per tool, static, rides `tool_invoke_count`'s registration info); declared-cold tools trigger the cold path at call time (transcript persist + prune before flush: history takes final state, transcript takes the minimal replay set), everything else stays hot with zero flushes. Gravity never branches on local vs remote — execution location lives in target resolution (user namespace + node alias + capability from the tool list), invoke targets come from the tool list, not from Gravity code.
- [ ] Phase 3 — Compression as a parallel side branch: when the Krystallizer's fetched view carries a compression marker (watermark reached), Gravity fires TWO concurrent requests from the same immutable prefix — main branch `[H] + [U_n]` answers the user (critical path, normal streaming), side branch `[H] + [compression instruction]` produces the summary. Prefix KV is shared (same-prompt fork — inference servers natively reuse concurrent prefix requests); the side branch pays only its delta. Summary lands before U_{n+1}: the session swaps to `[S] + [recent tail]` at the typing gap — zero user-perceived latency, no mixed-turn. Idle/no-turn triggers (cache TTL cooldown): the side branch is fired standalone (CLI idle tick / Prism timer / Aura `@cron` booth) — off every critical path, pure cost decision. Memory-tool extraction runs on the same branch pattern (past-oriented read branch, output to external state).

## Milestone B — Distributed execution

- [ ] Phase 4 — Aura Booth binding (`crates/booth`): the same execution function registered as a Booth type; one turn event = one execution. CLI becomes a for-loop over the same function; Booth is its single call.
  LANDED 2026-10-10 (second cut — the turn is FULLY in the booth, streaming end to end): two python booths — the provider (`httpx.stream` SSE → generator, `yield` per token, key custody via `key_env` name, the value never in the module or args) and the turn (`turn` handler is a GENERATOR: fetch the projection from mem-server over HTTP → assemble the prompt → `ctx.iterate` the provider yielding each token straight through → append the one-ts-two-subs exchange AFTER the stream ends). The streaming residual is CLOSED by this cut: per-token deltas cross as envelope items while the stream is live — prism's `turn.delta` contract rides it unchanged. Booths hold no connection state: store_url/endpoint/model/key_env ride the turn args (deployment facts the caller supplies per call). Test recipe then: `PYTHONPATH=<nix-python lib-dynload>:<site-packages> RUSTFLAGS="-L <nix-python libdir>" cargo test -p gravity-booth --features python`.
  SUPERSEDED 2026-10-13 (carrier ruling — gravity is a pure-Rust project; no embedded interpreter): the python carrier cut is retired. Both booths are Rust guest processes speaking the induction pipe protocol (`~/world/induction`; frame vocabulary per ADR-0034's `{item, done}` envelope — single-call and stream share the one envelope shape, `done: true` closes the boundary). The turn booth is an `induction-guest` binary: streaming state lives in the guest process (the process IS the stream state — the old "Rust body carries no stream state" note named the in-process `Body::Rust` closure arm, whose only limitation is lacking resident state to hold an iterator; a resident child process has exactly that). The provider booth is likewise an induction guest (SSE → envelope per pull round). `crates/booth` registers both via `BoothType` process spec (`language = "induction"`), same interface_schema contract (auth block on `turn`), same envelope semantics over the wire — prism's `turn.delta` contract unchanged.
- [x] Phase 4.1 — Re-land the booth crate on induction-guest (supersedes the python cut above): two guest binaries (`gravity-turn`, `gravity-provider`) + registration; the provider's SSE parse stands in for the real endpoint first (fixture stream), then wire OpenAI SSE in Phase 1.
  LANDED 2026-10-13 (gravity `34dd5e5` + `72886a5` + `08ec0c3`; induction `1358e64` + `0c3ab86`; prism `3ccb070`): both guests speak the induction pipe (CBOR codec — the self-delimited document form skips the per-frame JSON quoting overhead). Each guest has a Start handler `.on(name)` (the realm addresses the stream by the handler name — `stream` / `turn`) plus the reserved `.producer()` pull face; a plain `.producer()`-only guest never opens (the Start falls into "no such handler" → terminal-wrapped error → no stream). The turn's stream IS the turn: Start fetches the projection, opens the provider stream through the guest Ctx's NEW iterate consumer arms (`ctx.iterate_start/next/dispose` — the induction face of ADR-0034's pull loop, closing the Phase 4.21 residual), re-emits deltas, and the terminal round appends the one-ts-two-subs exchange (turn args captured in process state — the pull handler only sees the guard's `{stream_id, round}`). The SSE wire decoder has ONE home (`gravity-core llm::sse`, feed/decode protocol; the provider guest and any streaming consumer share it). The turn declares `.auth({turn:true})` — the induction schema's auth pass-through restores prism's gate (fail-open without it, found by turn_e2e). Spawn specs overridable per deployment (`GRAVITY_PROVIDER_BIN`/`GRAVITY_TURN_BIN` — prism's turn_e2e points at gravity's workspace build). prism's `register_executor` delegates to `gravity_booth::register` (no carrier feature gate, no PYTHONHOME/PYTHONPATH for this plane).
  Gates: gravity 3/0 booth contract tests (streaming round trip, append after done, failed provider appends nothing) + workspace 10/0, clippy 0, **no python in gravity's own graph**; induction 33/0 + clippy 0 (auth pass-through); prism turn_e2e 5/5 (auth gate, streaming, cancel, duplicate-submit refusal).
- [ ] Phase 4.5 — Unified call model adoption: tool calls go through `ctx.invoke()` (Aura CallSlot) — target = user namespace + node alias + capability (e.g. `probe:home-pc:read_file`); two-tier waiting handled by the runtime behind one `await` per call-site (hot: park on oneshot; cold: entry-split — no park, transcript flush, task ends, re-entry on result). Retention-window residency: executor stays in memory between calls/turns of the same session, session persisted at turn end or expiry; crash within window rebuilds from event stream. Multi-machine orchestration (e.g. "send the file from home PC to office PC") = two invokes composed in the turn loop — no remote/local branching in Gravity code.
- [ ] Phase 5 — Skill pull-through: on each tool call, fetch skill spec from Krystallizer via the pull-through path (Probe → Gravity → Krystallizer, never direct); view processing + `tool_invoke_count` weight write-back at this data gate.
- [ ] Phase 6 — CLI over Prism WS: wrap the WS protocol for remote sessions; local CLI (direct Krystallizer) and remote CLI (via Prism) share one protocol surface.

Deferred gates:

- FaaS driver: same execution function on serverless platforms — only after the Aura Booth path is stable; no new code, just another driver of the function.
- Multi-model routing: model selection per turn/session — after the single-model path is proven; LLM identity stays Gravity-side (cache binding), Krystallizer never learns it.
